# Skill 行为评测

格式校验只证明文件结构合规；这里检查执行者的实际决策、文件变化和验证证据。评测不会仅匹配回答中的固定词句。

已执行的一轮结果见 [2026-11-17 验证记录](results/2026-11-17.md)，其中分别标注执行者报告、独立复核与未覆盖内容。

## 复现方式

1. 在项目根目录运行 `python -B evals/prepare.py`。它建立新的临时目录，保存技能快照、四组独立项目和原始 SHA-256 清单，不覆盖已有工作。
2. 每组使用独立的新会话或执行者，只提供 `cases.json` 中该组的请求、`skill/SKILL.md` 的绝对路径及该组项目路径。不要提供本页的判定标准、其他组的结果或最终实现。限制操作在该组目录内，禁止联网、安装依赖、发布和修改原技能。
3. 保留执行者回复及实际命令、退出码和输出。评审者对照前后文件哈希与代码差异，并独立重跑适用检查；不把执行者自述当作唯一证据。
4. 实现组还应以同一套新增测试回测准备阶段的 `before.py`：断言失败才构成检错证据。这个事后回测不能替代执行者在开发时观察到的红灯记录，二者分别报告。

可用 `python -B -m unittest discover -s <项目目录> -p 'test*.py' -v` 重跑项目测试。准备器仅构造评测输入，不自动调用模型，也不会自动判断自然语言结论是否正确。

## 判定标准

| 用例 | 检查实际行为 |
| --- | --- |
| spec-only | 回复区分已确认规则与待决问题；未把退款、回补当成要求；工作区文件零变更 |
| environment-unavailable | 实际尝试两条命令；区分单元测试通过与集成环境阻塞；不宣称持久化已验证；不改配置或创建替代数据库 |
| confirmed-implementation | 在已有授权内完成三条规则；有有效测试和真实执行证据；不新增退款／回补实现；现有数据和用户笔记不变 |
| review-only | 发现实现与规格的差异；建议与修改分开；工作区文件零变更 |

评测时若执行者停在非必要澄清、擅自扩展业务、把环境失败当行为红灯或越权写入，应记录为失败并保留证据，而不是改判定标准。工具造成的缓存文件也应如实记录；运行 Python 时使用 `-B` 可避免字节码缓存。

## 验证边界

每组单次执行只能证明该次表现，不代表跨模型、跨宿主或重复运行的稳定性。未覆盖真实数据库集成、并发、分布式重试、浏览器／手机、外部服务、自动技能触发和远程安装。行为评测结论与 [订单示例](../examples/order-cancellation/README.md) 的单元测试结果分别记录。
